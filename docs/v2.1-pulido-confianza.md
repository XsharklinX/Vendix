# v2.1 - Pulido y confianza

Objetivo: hacer que Vendix se sienta mas segura, clara y profesional para uso diario sin romper los flujos existentes.

## Implementado

- Papelera operativa para productos, clientes, proveedores y empleados.
- Restauracion desde UI con revalidacion automatica de listas.
- Soporte backend para listar eliminados con `deleted=only`.
- Eliminacion logica usando `deletedAt` en los modulos principales.
- Filtros frecuentes persistentes por negocio en inventario, clientes, proveedores y empleados.
- Dashboard con skeletons iniciales y error reintentable para widgets criticos.
- Componentes base con mejor soporte dark mode: empty states, errores, paginacion y skeletons.
- Pantalla de estado del sistema en Configuraciones.
- Endpoint `/api/system/status` con version, entorno, inicio del servidor y rutas locales cuando la app corre empaquetada.
- Electron ahora expone al backend version de app, ruta de datos de usuario, ruta de base de datos y fecha de actualizacion del ejecutable.

## Verificaciones

- `npm run build:backend` completado correctamente.
- `npm run build:frontend` completado correctamente.

## Riesgos y notas

- La papelera depende de que cada tabla tenga `deletedAt`; ya existe para los cuatro modulos cubiertos.
- La restauracion no resuelve conflictos de datos por si sola. Si en el futuro se agregan restricciones unicas mas estrictas, conviene validar duplicados antes de restaurar.
- El build frontend mantiene advertencias no bloqueantes de Vite/PostCSS ya existentes.
- El bundle de Inventario sigue siendo grande; conviene optimizarlo en una fase de performance separada.
- La pantalla de sistema muestra algunas rutas solo en Electron empaquetado; en desarrollo puede mostrar `No disponible`.

## Pendiente sugerido

- Agregar busqueda y filtros dentro de cada papelera si el volumen de registros eliminados crece.
- Registrar quien restauro cada entidad con un detalle mas visible en auditoria.
- Agregar pruebas E2E para eliminar/restaurar en los cuatro modulos.
- Optimizar bundle de Inventario separando dependencias pesadas por lazy loading.
