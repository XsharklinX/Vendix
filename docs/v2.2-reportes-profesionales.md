# v2.2 - Reportes profesionales

Objetivo: que el dueño pueda tomar decisiones y compartir informacion operativa sin depender de hojas manuales.

## Implementado

- Exportacion desde Reportes a PDF usando la vista imprimible existente.
- Exportacion a Excel compatible mediante CSV UTF-8.
- Reporte de utilidad por producto.
- Reporte de utilidad por cliente.
- Aging de cuentas por cobrar con rangos `0-30`, `31-60`, `61-90` y `90+`.
- Reporte fiscal claro con ventas, NCF, impuestos y anulaciones.
- Boton para copiar resumen diario/cierre Z para WhatsApp.
- Snapshot persistente al cerrar caja mediante `DailyCloseSnapshot`.
- Endpoint para consultar snapshots diarios recientes.
- Migracion `20260703000000_v2_2_daily_close_snapshot`.

## Endpoints nuevos

- `GET /api/businesses/:businessId/stats/profitability?groupBy=product|client&from=YYYY-MM-DD&to=YYYY-MM-DD`
- `GET /api/businesses/:businessId/stats/aging-receivables`
- `GET /api/businesses/:businessId/stats/fiscal-summary?month=YYYY-MM`
- `GET /api/businesses/:businessId/stats/daily-close-snapshots`

## Verificaciones

- `npm run build:backend` completado correctamente.

## Riesgos y notas

- "Excel" se entrega como CSV compatible con Excel, no como `.xlsx` nativo. Es suficiente para abrir/compartir, pero una fase futura puede generar `.xlsx` real con estilos.
- Los snapshots se crean al cerrar caja. Dias anteriores sin cierre no tendran snapshot historico hasta que se genere uno manualmente o se agregue backfill.
- La utilidad usa costo guardado en `TransactionItem`. Si ventas antiguas no tienen costo correcto, el reporte reflejara ese dato historico.
- `Reportes.tsx` mantiene textos con encoding raro heredado; conviene hacer una limpieza dedicada para evitar mezclarla con cambios funcionales.
