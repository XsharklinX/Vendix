# v2.4 - CRM util, no decorativo

## Objetivo

Convertir el registro de clientes en una herramienta operativa para generar ventas repetidas, dar seguimiento a oportunidades y usar la fidelizacion directamente en el punto de venta.

## Implementado

### POS con puntos/canjes

- El POS permite aplicar puntos de fidelidad del cliente seleccionado como descuento directo.
- El backend valida que el cliente tenga puntos suficientes antes de completar la venta.
- Al registrar la venta se crea automaticamente el canje y luego se acreditan los puntos ganados por el monto final de la venta.

### Recordatorios CRM en Planner

- Planner ahora muestra recordatorios CRM pendientes y vencidos.
- Cada recordatorio incluye cliente, fecha, nota y acceso rapido a WhatsApp cuando existe telefono.
- El panel de Planner considera estos recordatorios dentro del estado general de tareas pendientes.

### Alertas de clientes en riesgo y campanas simples

- Clientes incluye una seccion de campana por inactividad.
- Permite elegir ventanas de 30, 60, 90 o 120 dias sin compra.
- Se puede copiar una lista resumida para contactar clientes por fuera de la app.

### Etiquetas manuales

- El formulario de clientes permite agregar etiquetas manuales separadas por coma.
- Las etiquetas manuales se combinan con los segmentos automaticos existentes para mantener compatibilidad visual.
- Se agrego el campo `manualTags` al modelo `Client`.

### Seguimiento de cotizaciones por vencer

- Planner muestra cotizaciones pendientes cuya fecha de validez vence dentro de los proximos 7 dias.
- Las cotizaciones vencidas o proximas a vencer quedan visibles como oportunidades de seguimiento.

### Historial de precios/descuentos por cliente

- La base existente de ventas por cliente queda conectada al flujo de POS con descuentos manuales y canjes.
- Esta fase deja preparado el camino para una vista dedicada de historial comercial por cliente sin duplicar datos.

## Backend

- `GET /api/businesses/:businessId/clients/crm/reminders`
  - Devuelve recordatorios CRM incompletos con fecha vencida o proxima.

- `GET /api/businesses/:businessId/clients/crm/inactive-campaign?days=60`
  - Devuelve clientes sin compras recientes para campanas simples.

- `POST /api/businesses/:businessId/transactions`
  - Acepta `loyaltyPointsRedeemed` y `loyaltyDiscountAmount`.
  - Valida saldo de puntos antes de completar la transaccion.
  - Crea el registro de canje de fidelidad y actualiza el saldo del cliente.

## Frontend

- `Vender`
  - Bloque de canje de puntos visible al seleccionar un cliente con puntos disponibles.
  - Calculo separado de descuento manual y descuento por puntos.

- `Clientes`
  - Campo de etiquetas manuales.
  - Campana por clientes inactivos con selector de dias y copia rapida.

- `Planner`
  - Recordatorios CRM.
  - Cotizaciones por vencer.

## Riesgos y pendientes

- El canje usa una equivalencia simple: `1 punto = 1 unidad monetaria`. Si se necesita otra tasa, conviene agregar configuracion por negocio.
- Las etiquetas manuales se guardan como JSON en texto para minimizar impacto; una taxonomia global de etiquetas requeriria modelo propio.
- La campana de clientes inactivos genera una lista accionable, pero aun no envia mensajes masivos desde la app.
- El historial detallado de precios/descuentos por cliente todavia no tiene una pantalla dedicada; puede construirse sobre ventas, items y transacciones existentes.
