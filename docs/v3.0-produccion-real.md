# v3.0 - Produccion real

## Objetivo

Reducir el riesgo de romper flujos criticos antes de cobrar por la app, agregando pruebas, CI y observabilidad basica.

## Implementado

### Tests backend agregados

- Cotizaciones:
  - crear cotizacion
  - convertir cotizacion en venta
  - descontar inventario al convertir
  - rechazar conversion si no hay stock suficiente

- Backup:
  - exportar respaldo
  - validar respaldo antes de importar
  - importar respaldo en otro negocio
  - evitar duplicados en importaciones repetidas
  - rechazar archivos sin entidades importables

- Cliente/deuda:
  - venta pendiente aparece como deuda del cliente
  - cliente con deuda queda segmentado como `En riesgo`
  - etiquetas manuales conviven con segmentos automaticos

### Smoke tests frontend

- Login
- POS / Vender
- Inventario
- Caja

Tambien se corrigieron selectores existentes del POS para que no fallen cuando hay botones de categoria con el mismo nombre del producto.

### CI

- Nuevo workflow `.github/workflows/ci.yml`.
- Corre en PR, `main` y ramas `codex/**`.
- Pasos:
  - instalar dependencias
  - generar Prisma Client
  - typecheck backend/frontend
  - tests backend/frontend
  - build de produccion

El workflow de release ya dependia de tests antes de publicar; CI separado da feedback antes de llegar al release.

### Scripts raiz

- `npm run typecheck`
- `npm run typecheck:backend`
- `npm run typecheck:frontend`
- `npm test`
- `npm run test:backend`
- `npm run test:frontend`

### Medicion de errores

- Cada request recibe `X-Request-Id`.
- Las respuestas `5xx` se registran con:
  - request id
  - metodo
  - ruta
  - status code
  - duracion

Esto deja una base para soporte y para conectar Sentry/OpenTelemetry mas adelante.

## Limitacion encontrada

Los tests backend no completan localmente en este entorno porque Prisma Client queda colgado con el runtime Node local (`v25.x`) usado por npm. Prisma 5 esta orientado a Node LTS; el CI nuevo fuerza Node 20, que es el runtime recomendado para validar backend.

Se ajusto el setup de Jest para usar una DB SQLite aislada `backend/prisma/test.db`. El setup intenta `prisma db push`; si el engine local falla creando DB, usa `dev.db` como plantilla de schema para no bloquear el entorno local.
