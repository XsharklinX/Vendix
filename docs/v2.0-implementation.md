# v2.0 - CRM y fidelizacion

Fecha: 2026-05-28  
Estado: implementado base

## Alcance implementado

- Notas libres por cliente.
- Recordatorios por cliente con fecha y marcado como completado.
- Timeline cronologico por cliente con ventas, deudas, notas, recordatorios y canjes de puntos.
- Puntos de fidelizacion acumulados automaticamente en ventas completadas.
- Canje manual de puntos como descuento registrado en historial.
- Segmentacion automatica calculada en backend: `VIP`, `Nuevo`, `Frecuente`, `En riesgo`.
- Pantalla `Clientes` actualizada con KPIs, busqueda por segmento, puntos y panel CRM por cliente.

## Backend

- `Client.loyaltyPoints` guarda el saldo actual de puntos.
- `ClientNote` guarda notas y recordatorios.
- `LoyaltyRedemption` guarda canjes de puntos.
- `GET /businesses/:businessId/clients` ahora devuelve deuda, ventas acumuladas, ultima compra, puntos y segmentos.
- `GET /businesses/:businessId/clients/:id/timeline` devuelve historial unificado.
- `POST /businesses/:businessId/clients/:id/notes` crea nota o recordatorio.
- `PUT /businesses/:businessId/clients/:clientId/notes/:noteId` actualiza o completa recordatorio.
- `DELETE /businesses/:businessId/clients/:clientId/notes/:noteId` elimina nota.
- `POST /businesses/:businessId/clients/:id/redeem-points` registra canje.
- `POST /transactions` suma 1 punto por cada 100 de monto en ventas completadas con cliente.
- Cancelaciones/devoluciones de ventas completadas revierten puntos calculados.

## Frontend

- `Clientes` conserva CRUD y exportacion CSV.
- Nueva columna de segmentos automaticos.
- Nueva columna de puntos.
- Nuevo panel `CRM` con resumen, nota/recordatorio, canje y timeline.

## Reglas actuales

- `VIP`: cliente marcado VIP, compras acumuladas >= 50,000 o 20 ventas completadas.
- `Nuevo`: creado hace 30 dias o menos y con 0-1 ventas completadas.
- `Frecuente`: 5 o mas compras completadas en los ultimos 90 dias.
- `En riesgo`: tiene deuda pendiente o no compra desde hace 60 dias.
- Puntos: `floor(monto / 100)` por venta completada.

## Riesgos y deuda tecnica

- El canje de puntos queda registrado como historial CRM, pero no se aplica automaticamente dentro del POS como descuento de una venta nueva.
- La tasa de puntos esta fija en codigo; conviene hacerla configurable por negocio.
- Los recordatorios se ven en el timeline del cliente, pero aun no se integran al `Planner`.
- La segmentacion es calculada, no persistida. Esto evita datos obsoletos, pero no permite edicion manual de tags.
